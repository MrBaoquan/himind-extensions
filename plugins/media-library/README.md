# 媒体资源库

## AI 生成与加工（2.15）

“AI 生成”提供图片生成、改图、视频和配音工作区，后台任务也可进入生成记录。图片详情提供“修改图片 / 生成视频”。模型、服务、凭据和执行归底座 Agent；插件不调用 Provider HTTP，不保存 service 默认值。

需要底座 `media.job.start/list/get/cancel` 与 `media.asset.import` 接口。启动时探测真实能力，旧 Agent 显示更新说明并停用生成按钮，已有素材功能继续可用。视频或语音未配置时显示设置说明，不模拟成功。

一次生成对应一个持久会话和幂等提交键。关闭窗口后由 Agent 继续执行；重开核对原任务。同步请求超时或 Agent 中断后，底座标记“需要核对”，不会自动重复调用模型。原同步 media.* 能力保持兼容。

默认预览后选择入库。入库失败重试只复制原制品；按目标库与 SHA-256 去重，同时保留每次生成记录与完整 Generation Manifest。改图使用受控参考副本，保留原素材。配音标记为 voiceover，不进入 BGM。自动入库在生成工作区打开时处理，关窗期间候选由 Agent 保留；当前保留策略不自动过期。

正式资产保存实际模型、完整输入、参考素材 ID 与哈希、结果哈希和用量状态；目录事件附同份 Manifest。未知费用、seed、许可保持未知。候选、原执行与正式素材是不同对象；“新建”生成会产生新的模型调用。

`com.himind.media-library` 是 HiMind Agent 的媒体发现、采纳与共享资源库插件。

## 主要能力

- 在线检索：Pexels 图片/视频、Unsplash 图片、Freesound 音频
- 本机文件夹：注册目录、分批扫描、增量刷新、候选索引
- 资源库：用户主动采纳在线或本地素材，不会把搜索结果自动加入
- 本地/SMB：同一套 Library 抽象支持本地目录和 SMB UNC 目录
- 快速检索：SQLite + FTS5 本机索引
- 预览：图片、视频、音频统一预览入口
- 来源记录：作者、许可证、原始链接、SHA-256 和采纳人
- 多人共建：SMB 资源库使用每用户追加式 JSONL 元数据

## 统一采集入口（2.10.0）

2.11.0 增加了 BGM 发现与音轨入库：

- 本机视频/音频预览中展开“提取音频”或“裁剪音频并入库”，填写秒数或从播放器标记时间，试听后选择本机库和 WAV、MP3、M4A 格式。开始为 0 且结束留空时提取完整音轨，格式转换不提高原始音质。
- 媒体库负责顶层任务和入库，媒体处理工具 2.3.3 负责确定性音频处理。后台进度/完成回执独立于窗口和短期调用通道，任务支持取消与重试，原文件保留。
- “在线发现 → 抖音 → 音乐 / BGM”按平台音乐 ID 聚合视频用曲并展示已加载样本中的使用次数；默认关键词“热门 BGM”属于视频搜索，不代表官方音乐榜单。无可靠音乐 ID 的视频计入未识别样本，不按歌名强行合并。
- 聚合结果选择具体视频“提取音频”，或添加链接后选择“仅音频 · MP3”和“作为 BGM 保存”。音轨可能含口播、环境声或二次加工，平台原声身份不等于歌曲识别，不执行音源分离。
- “素材 → 我的 BGM”检索入库音频，支持名称、平台用曲标题/作者和时长筛选；预览显示原作品、音乐身份与裁剪参数，完整来源指纹可通过来源能力读取。未知许可保持未知。
- `media-library.audio.start` 接收素材 ID、目标库、毫秒片段、格式和幂等标识，不接收任意源路径；`media-library.music.discover` 返回样本依据、采样时间、识别覆盖率和用曲列表。
- 音乐、用曲、样本观察和派生关系独立记录于本机插件数据库，文件按 SHA-256 去重。本版不提供跨客户端音乐关系同步、官方音乐榜单、跨平台音频指纹、趋势分析或 AI 音源分离。

- 主导航：素材、在线发现、收藏、精选、库；右上角提供添加链接与后台任务。
- 在线发现保留素材站搜索，并接入抖音、哔哩哔哩、YouTube 官网搜索页；抖音需先连接。正常搜索自动返回，官网要求验证时显示受控窗口；不绕过登录、验证码或站点限制。各平台实际可用性以当次结果及验收记录为准，点击下载后自动读取单个作品信息。
- 每次读取最多 60 条官网已加载的作品线索，12 条一页，翻页复用 10 分钟短期快照；游标绑定平台、关键词和账号，换号或过期后需重新搜索。搜索结果不会自动入库，临时封面与会话秘密不写入收藏或结果缓存。
- 2.12.3：抖音视频结果及音乐用曲的视频样本显示作品点赞、收藏、评论、分享数，万/亿缩写支持悬停查看完整数值及获取时间。仅补充当前页的 12 项，最多 3 个并行详情读取、总预算 8 秒；相同快照复用观察结果，重新搜索更新。缺失、超时或平台未提供的字段显示“—”，真实零值显示 0，不因统计不可用而丢弃视频结果。这些是视频互动量，不代表音乐全平台热度；不会执行点赞或平台收藏操作。
- 添加链接后可收藏、选择视频/音频/字幕，并下载入库或仅保存文件；播放列表暂留旧下载工具。
- 平台连接和下载组件在设置的“平台与下载”；媒体库首次使用需连接一次，旧工具会话保留。
- 后台任务独立运行，关闭视图继续；重试可复用已下载文件，记录移除不会删除文件。
- 开发验收快捷键 F8 或 Ctrl+Shift+G 只保存当前真实 DOM 的数值几何，不采集文本、链接、输入值或会话。

### 平台支持与边界

| 来源 | 关键词搜索 | 在线预览 | 单作品采集 | 本轮验证 |
| --- | --- | --- | --- | --- |
| 抖音 | 官网作品页，需连接 | 打开作品页面 | 视频、音频，受作品权限限制 | 航拍、旅行各两页；两种视频格式入库并播放；MP3仅保存成功 |
| 哔哩哔哩 | 官网公开作品 | 打开作品页面 | 以解析出的格式为准 | 航拍、科技各两页；480p入库并播放 |
| YouTube | 官网公开作品，需网络可达 | 打开作品页面 | 以解析出的格式为准 | 两组航拍关键词各两页；480p入库并播放 |
| Pexels、Unsplash、Freesound | 原有API来源，需配置 | 素材预览 | 原有取用路径 | 保留原契约；未新增付费或真实密钥验收 |
| 其他网页 | 不提供通用关键词搜索 | 原站页面 | yt-dlp可解析的单作品 | 不承诺所有站点；以本次解析与权限为准 |

搜索读取官网正常渲染的作品，不代表视频直链已经可下载。官网可能暂时无结果、限流或要求验证；界面保留取消、错误和重试路径。搜索结果与收藏保存稳定作品链接，下载完成后才可以在素材页直接播放。字幕仅在解析返回语言时显示；字幕父作品关联与多格式一致性有隔离测试，未把无字幕作品作为真实字幕成功样例。播放列表、合集和旧在途任务继续使用媒体下载工具。

### 迁移与回退

- 在“后台任务 → 旧下载记录”导入旧工具已结束任务，只增加只读历史引用；重复导入不重复新增，不移动、重新下载或删除原文件，在途任务仍由旧工具管理。面板最多展示最近200条，单次导入最多10000条，更多历史在旧工具查看。
- 新旧插件拥有独立的运行时和站点会话；媒体库通过“平台与下载”安装组件、连接一次抖音。旧会话和运行时保留，不复制跨插件凭据。连接完成后复用受控会话，不需粘贴Cookie。
- 媒体采集助手0.2.0默认调用媒体库，旧工具依赖为可选；技能稳定ID和目录保持不变。旧的 `media.downloader.*` 接口仍归原插件，未伪装成新接口别名。
- 回退时先让新后台任务结束或取消，再在扩展开发入口激活已保存的旧候选。新库条目、下载文件和历史均保留；回退不恢复覆盖整库数据库，不让两个owner同时写同一任务。

Windows桌面验收覆盖1280×794与760×520逻辑内容区、DPR2；非空搜索、收藏、解析、任务和旧历史均有真实交互与DOM数值证据。弹窗共用一个滚动视口，标题、正文、底部操作基线一致；16px内边距与15px系统滚动条占位分别测量。详见[统一交付验收记录](../../docs/audits/media-library-unification-2026-11-14.md)。

## 界面结构

- 主界面只保留搜索、范围/类型筛选和结果，不展示资源库、文件夹或凭据配置。
- 资源库、本机文件夹、在线来源和索引状态统一收进“媒体库设置”弹窗。
- 音频卡片可直接播放/暂停并显示进度；点击卡片其他区域仍进入详情。
- 搜索、设置和刷新使用带 tooltip 与可访问名称的 SVG 图标按钮；非编辑区域禁用网页右键菜单。
- 默认入库资源库只在设置中选择；素材详情可以为单次采纳切换目标资源库。
- 资源库可以改名、切换访问模式或从 HiMind 移除；本机来源可以改名或移除索引，两者都不会删除磁盘文件。
- 在线筛选使用搜索区下方的内联折叠面板，不再以浮层遮挡结果。
- 音频卡片播放态使用独立 pause SVG，暂停后恢复 play SVG。
- 点击素材卡片打开右侧预览面板；详情支持上一项/下一项和键盘左右切换。
- 设置和预览均支持 Esc 关闭、背景滚动锁定和焦点返回。
- 未保存修改、移除资源库或本机来源等确认操作使用应用内 `alertdialog`，不调用浏览器原生确认框；取消、遮罩关闭、焦点陷阱和焦点返回均已覆盖。

## 入库元数据与快速检索

- 入库前可以修改素材名称；物理文件名会保留源文件扩展名。
- 可以填写分类路径和标签。分类路径是逻辑分类，不改变 `assets/<sha-prefix>/` 的内容寻址存储结构。
- 标签、分类路径和标题会写入 SQLite FTS 索引；已采纳资源还会把标签和分类路径写入 SMB 用户目录的 catalog JSONL。
- 搜索支持名称、文件名、路径、许可证、标签和分类路径的关键词匹配，并继续支持图片/视频/音频类型与来源范围筛选。
- SHA-256 去重优先于重复复制；同一素材再次入库时保留已有名称和元数据。

## 大数据量检索

- SQLite search_fts_v2 分列索引标题、文件名、路径、标签、分类路径、许可证和作者。
- 查询使用 BM25 字段权重、类型/范围/资源库前置过滤和稳定游标分页。
- 宽泛查询先处理最近 1000 条匹配窗口；窗口不足时回退全局 FTS 排名。
- 1–2 字中文查询使用受限索引扫描兜底，避免无界全表扫描。
- 组合索引覆盖最近资源、类型和资源库范围，旧数据库首次打开会自动回填 FTS v2。
- 公开基准：10 万条常见关键词 P95 约 84ms、组合筛选约 21ms、最近资源约 5ms。

## 凭据管理

在线来源凭据不保存在插件目录。插件在 `plugin.json` 中声明：

- `pexels.api`
- `unsplash.api`
- `freesound.api`

用户在 HiMind Agent 的「账号与凭据」中配置。插件进程通过
`HIMIND_CREDENTIAL_BROKER_URL` 和一次性 token 按能力调用获取凭据。

旧版 `provider-keys.json` 和 `media-library.provider.configure` 已移除。
升级到 2.0.0 后需要重新在 Agent 凭据中心录入密钥。

## 资源库结构

本地资源库或 SMB 共享库的根目录结构：

```text
library/
├─ assets/
└─ .himind-media/
   ├─ library.json
   └─ catalog/
      └─ users/
         └─ <actor>.jsonl
```

- `assets/` 保存资源文件
- `library.json` 使用 `library_id` 识别同一共享库
- `catalog/users/*.jsonl` 每个用户只写自己的事件文件，避免多人同时写同一文件
- 插件索引数据库位于 Agent 的插件私有数据目录，不放在 SMB 上

SMB 资源库必须使用 UNC 路径，例如：

```text
\\nas\media\team-library
```

本地资源库支持：

- `copy`：复制到资源库 `assets/`
- `reference`：只登记原文件路径

SMB 共享库只支持复制，避免把某台电脑的本地路径写入共享目录。

## 工作流

```text
在线搜索 / 添加本机文件夹
        ↓
候选索引与预览
        ↓
用户选择目标资源库并点击“添加到资源库”
        ↓
复制/上传、SHA-256 去重、写入来源与许可证
        ↓
资源库条目、标签和检索索引
```

## 安全与限制

- 在线素材进入 SMB 共享库时，必须明确确认允许再分发
- 未知或许可证不明确的资源默认不能进入 SMB 共享库
- 预览接口只允许读取已索引候选或已采纳资源
- SMB 认证优先使用 Windows 集成身份；多 SMB 账号 Profile 属于后续 Agent 能力
- 当前插件目标平台为 Windows x64
- 本期不使用语义向量索引；先提供文件名、标题、标签和路径的 FTS/包含检索
- SMB 实时文件监听不在本期范围，使用打开页面时刷新或手动分批扫描

## 检索与筛选（v3）

- 搜索支持名称、路径、标签/分类路径（资源库）、文件夹、分辨率档、时长档。
- 本机筛选：文件夹（facets 统计）、最小分辨率（4K/2K/1080p/720p）、时长区间。
- 在线来源继续使用方向/最小宽度/最小时长筛选；本机与在线同时展示时互不阻塞。
- `media-library.asset.facets` 返回文件夹、类型、分辨率、时长分布，供筛选面板使用。
- 短中文（1–2 字）走 `search_cjk` 逐字索引：标题/文件名/路径/标签按单字展开，
  查询编译为连续字短语；50 万条下 2 字中文 P95 约 6ms（先取最近 1000 条样本排序）。

## 精选与沉淀（v3）

- 从当前搜索结果创建「精选集」，设定目标数量与精选库目录。
- 自动预选：关键帧 pHash 聚类 + 清晰度/曝光/分辨率/时长质量分 + 聚类配额，保证覆盖不同镜头。
- 精选工作台：逐条「入选 / 备选 / 排除」，进度实时更新；自动结果可被人工覆盖。
- 沉淀：按来源相对路径写入精选库；同卷默认硬链接（不占额外空间），跨卷自动复制，
  也可只登记引用；重复沉淀按文件大小幂等跳过，并写 `.himind-media/curation.jsonl` 血缘。

## 大文件预览（v3）

- 视频/音频通过 Agent 的 `/plugin-media` 只读 Range 端点播放，支持拖动进度，不把整段
  媒体读进内存，也不依赖 `file://`。
- 插件用 Agent 注入的每机密钥签发短时票据；端点只监听 `127.0.0.1`，只服务已索引资产。

## 用户标记与双存储（v3）

- 素材详情支持标签和 0–5 星评分；保存后立即进入检索（标签参与 FTS）。
- 每个本机来源可选标记存储方式：
  - `db`：只写本机数据库（默认）；
  - `jsonl`：把标签/评分事件追加到 `<来源>/.himind-media/user-data.jsonl`，随素材盘一起搬走；
  - `both`：数据库 + 来源 JSONL 双写。
- 事件为追加式 JSONL，包含 `event_id/asset_id/op/tags/rating/actor/created_at`；DB 是物化视图。
- 设置页「本机文件夹」可查看每个来源当前的标记存储方式；添加来源时可直接选择。

## AI 视觉打标（v3）

- Agent 新增内置能力 `media.ai.describe`：输入本地图片或 data URL，调用已接入的多模态模型，返回标签/描述/质量分。
- 媒体库预览面板「AI 打标」按钮：取当前素材缩略图 → 调 `media.ai.describe` → 自动写入标签并显示描述/质量/tokens。
- 已实测 DeepSeek V4.1 Flash（`custom:deepseekv41f`）可识别真实航拍画面；单张约 400–700 tokens，延迟约 8–60 秒。
- AI 服务在「AI 服务」中配置；可在预览面板的「AI 服务」输入 `custom:<id>` 临时指定，留空使用激活服务。
- 未配置视觉模型或余额不足时，会返回明确错误，不影响索引/检索/预览。
- 效率相关参数：
  - `profile=fast`：只出标签，约 500 tokens/张；`full` 出标签+描述+质量，约 600+ tokens；
  - `profile=ocr`：只出画面文字，按行纯文本，写入素材备注并进入检索；
  - `max_edge`：批量建议 512，预览可用 768/1024；
  - `max_output_tokens`：快速模式 200，完整模式 400；
  - `reasoning_effort`：部分网关支持 `none/low`，可减少推理 token；
  - 结果按 `asset + profile + service + prompt 版本` 缓存，重复打标不再调用模型；
  - 精选批量打标按“相似组”只取代表帧调用一次，再把标签复制到同组素材。

### 视频起播优化（2.3.7）

相机原始素材普遍把 `moov` 写在文件末尾（3GB 文件里索引在最后 900KB），播放器必须先读完整个
`mdat` 才能开始，首帧要等数秒。媒体流端点现在做了三件事，都不改文件、不转码：

- **读取时把 moov 提前**：按原子表重组读取顺序（`ftyp → moov → mdat`），并实时修正
  `stco/co64` 里的样本偏移；客户端看到的是同一份数据、同一长度，只是索引在前。
- **按 4MiB 切段响应**：`Range: bytes=0-` 不再回整段文件，避免为拿索引而读满几 GB。
- **缓存与票据稳定**：`ETag + Cache-Control: private, max-age=300`，票据按整点对齐，
  同一小时内重开同一素材直接命中 WebView 媒体缓存；`.mov` 按 `video/mp4` 返回。

视图侧在搜索结果出来后预取一次元数据（只拉 moov，不播放），并在加载期间显示「正在加载视频…」。

实测（3.06GB / 4K / 132Mbps，development profile，18082）：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首帧就绪（loadedmetadata / canplay） | 6,253ms | 327 / 376ms |
| 同一素材再次打开 | 1,377ms | 461ms（缓存命中可到 24ms） |
| 首次拖动到 100s | — | 6.6s（冷读该区段） |
| 再次拖动到 100s | — | 62ms |

冷读首次拖动仍受磁盘/杀毒扫描影响，属于文件第一次被访问的成本；后续拖动与重开都是毫秒级。

### 后台批量作业（2.2）

- 批量打标改为 Agent 侧后台作业：`media.ai.tag.batch.start / status / cancel / resume / list`。
- 作业落盘 `agent_home()/media-ai-jobs/<job_id>.json`；关闭视图、甚至 Agent 重启都不丢结果，
  未完成条目会标成 `interrupted` 并回到 `pending`，可以继续跑。
- 并发默认 2，单条失败自动重试 1 次（`attempts=2`）；网关不认 `reasoning_effort` 时自动去掉再重试。
- 视图侧只用精选集 + 相似组代表帧：命中缓存直接写标签，其余提交后台作业；
  进度条显示 `已处理/总数 · 失败 · tokens`，可随时取消。
- 作业引用记录在插件库 `ai_job_state` 表，重开视图会按精选集自动接上上次的作业。
- 预算闸门 `media-library.ai.budget`：单次 $2 / 每日 $5 / 每月 $20，按 `ai_tag_cache`
  实际 token 估算；本次作业可用 token 上限通过 `budget_tokens` 传给 Agent 硬停。
- 实测：fast 单张约 560 tokens；full 波动很大（636–30,112），批量请用 fast。


## 精选与精选库（2.3）

精选是「从素材里挑出要留下的」的过程，精选库是这个过程的结果，二者都在「精选」视图里。

- **两个视图**：顶部「素材 / 精选」。素材负责搜索与浏览；精选负责挑选与入库，不再用模态盖住结果。
- **左列表**：所有精选，带状态徽标（草稿 / 进行中 / 已加入）、`入选 N / 目标 M`、目标库路径；点一下即切换。
- **进度带**：`全部 / 入选 / 备选 / 排除` 四段可点，点哪段筛哪段，直接看到「粗库 → 挑选」的比例。
- **工作区**：网格卡片，`入选 / 备选 / 排除` 三态；支持按相似组折叠、按质量或状态排序、
  `J/K` 上下移动、`1/2/3/0` 决策；相似组多于 1 条时可「只留最佳」（批量决策）。
- **目标精选库**：从资源库下拉里选，不再手填路径；没有就就地新建（`repository.create kind=curated`）。
- **加入结果**：显示 `新增 X · 已存在 Y · 失败 Z · 库内共 N 条`，可一键「打开精选库」。
- **精选库就是资源库**：`libraries.kind='curated'`，会出现在设置里的资源库列表（标「精选库」），
  条目写入 `library_items` 并进检索索引；搜索结果带「精选库」徽标，`scope=library` 能直接搜到。
- **AI 打标**：模式与服务收进「更多」，主工具栏只留动作；后台作业与断点续跑不变。

旧数据迁移：首次启动会把已有精选集的 `target_path` 自动登记成同名精选库（`<精选名> 精选库`）并回填 `library_id`；
目标目录位于系统临时目录时，界面上会提示「临时目录，重开后可能被清理」。

### 库详情与图标（2.5）

- 设置 → 资源库每行新增「查看」：打开库详情，分页列出条目（缩略图、分辨率、时长、大小），
  可打开目录，点条目直接在预览面板里翻页查看。能力：`media-library.holdings.items`。
- 界面用图标收敛文案：视图页签（网格/库）、来源徽标（库/本机/云 + 重复副本链接）、
  精选进度带（层/勾/书签/禁）、决策按钮、工具栏（魔杖/标签/更多）、打开目录与加入精选库。
- 「按相似组折叠」改为开关按钮（`aria-pressed`），在线来源筛选改为可切换的来源芯片，

- 窄窗（<980）精选列表可折叠；标题显示「精选 · N 个」。

## 库管理（2.6）

顶部多出第三个视图「库」，素材库与精选库都在这里管理；设置里的「查看」也会跳到这里。

- **条目列表**：表格 / 网格两种布局，显示缩略图、分辨率、时长、大小、标签与评分；
  表格里可直接改标签（回车保存、Esc 取消）和评分。
- **移出（软删除）**：选中条目点「移出」，默认只删索引，磁盘文件保留；
  移出后进入「回收站」，可「恢复」；移出时同步作废精选里的「已加入」记录，恢复时自动补回。
- **回收站**：`media-library.holdings.trash.list` 列出已移出条目，支持多选恢复；条目计数不含已移出内容。
- **重新扫描**：`media-library.holdings.rescan` 只报告差异（缺失 / 大小变化 / 未登记文件），不改数据。
- **同步精选**：`media-library.holdings.sync` 先预览差异，再把「不在精选里」的条目移出（仍只删索引）；
  新增条目仍走精选里的「加入精选库」，不会静默复制文件。老精选库首次打开会自动回填来源精选。
- **删除整个库**：断开引用它的精选、清掉该目录下的沉淀记录，磁盘文件不动。

新增能力：`media-library.holdings.item.remove`、`media-library.holdings.item.restore`、`media-library.holdings.trash.list`、`media-library.holdings.rescan`、`media-library.holdings.sync`。

> 能力 ID 遵循 ADR 0119：层级用 `.`、词内复合用 `-`，相邻段不重复（所以不会出现 `media-library.library.*`）。
> 改名前的旧 ID（`library.*`、`asset.ai_cache.*`、`asset.user_state`）只在插件进程内做转发兼容，不再出现在清单里。

## 自动整理（2.8）

「库」视图顶部的「自动整理」把整理流程压成一次点击：算方案 → 高置信直接入库 → 顺带 AI 打标 →
剩下拿不准的进复核队列。默认允许自动入库，所有动作都可撤销、不动源文件。

- **方案**（`media-library.organize.plan`）：取最近修改的候选（默认 120 条），按画质（清晰度/曝光/分辨率/时长）
  与 pHash 相似聚类打分，输出「自动入库 / 待复核 / 跳过」三摞，**不落文件**；
  已在库里的内容按 `content_key` 自动排除。老库重复整理不会翻动已有条目。
- **执行**（`media-library.organize.apply`）：高置信条目硬链接进库（跨盘自动复制），写库条目与检索索引，
  记录 `library_events`；`cleanup` 只清理**源文件已丢失**的条目，不会因为“这次没选中”就移出。
- **AI 自动打标**：入库后在后台用 fast profile 打标（每次最多 24 条，失败会提示原因，余额不足会明说），
  标签写回素材状态，库表格直接可见。
- **复核队列**（`organize.review.list` / `organize.review.decide`）：逐条「通过 / 排除」，也支持全部通过/排除；
  通过才入库，排除只跳过这一轮。复核期间不重绘列表，不会打断点击。
- **运行记录**（`organize.runs.list`）：每次整理的入库/清理/失败数量。

默认策略：`auto_ingest=true`、`quality_floor=45`、`similarity=12`、`per_cluster=1`、`max_items=60`（界面）、
`max_review=100`、`max_scan=120`、`mode=hardlink`、`cleanup=true`。批量打标沿用 AI 预算闸门（单次 $2 / 日 $5 / 月 $20）。

## AI 服务归属（2.9）

AI 服务（服务商、模型、密钥、预算、降级）**全部由 Agent 决定**，插件只表达任务：

- 插件不再保存或传递 `service`；`custom:<id>` 这类寻址不会出现在插件配置里。
- 打标只传任务参数：`profile`（fast / full / ocr）、`max_edge`、`max_output_tokens`。
- Agent 按能力绑定路由：`vision.describe` → 绑定服务（当前 dev 为 `deepseekv41f`），没有绑定才退回当前激活服务。
- 界面只读展示 Agent 回传的实际服务：`AI 服务：deepseek-v4.1-flash (向量潮汐) · deepseek-v4.1-flash`，
  批量作业也会把解析到的服务回填到作业记录里。
- 空返回不再算成功：Agent 批次会降分辨率重试，仍空则标记失败并给出原因。

## 运行时依赖（v3）

- `ffprobe`：读取图片/视频/音频的尺寸、时长、帧率、编码、音轨等元数据，必需。
- `ffmpeg`：生成视频首帧、音频波形、PSD/TIFF 等缩略图，必需。
- `exiftool`：RAW/HEIC/XMP/GPS 深度元数据，可选。
- 找不到时 `media-library.runtime.status` 会返回缺失项；文件名检索不受影响，元数据与缩略图标记为未就绪。
- 可用 `HIMIND_MEDIA_FFMPEG` / `HIMIND_MEDIA_FFPROBE` / `HIMIND_MEDIA_EXIFTOOL` 指定路径，否则查 PATH 与插件目录。

v3 新增能力：

- `media-library.asset.enrich`：批量探测元数据、生成缩略图/波形（支持按来源或指定资产）。
- `media-library.asset.detail`：读取单个资产的完整元数据。
- `media-library.asset.thumbnail`：批量返回缩略图 data URL。

## 下载流程精简（2.12.1）

- 搜索、收藏和视频预览的“下载”自动读取作品信息，直接选择格式和保存位置；不自动创建下载任务。
- 确认按钮按保存方式显示“下载并入库”或“开始下载”，音频显示“提取并入库”或“提取音频”。
- 手动添加链接后点击“继续”；读取失败可重试，修改链接会使旧结果失效。资源库读取与作品信息读取并行，关闭窗口后忽略旧响应。
- 下载和本地音频处理统一在“后台任务”查看，平台账号与组件位于“平台与下载”。内部 capability 与历史任务字段保持兼容。

### 2.13 桌面详情与预览

详情使用大预览、可折叠的信息栏与固定操作条。信息、整理、来源分别滚动；已知信息不等待媒体加载，播放失败可保留来源并单独重试。支持按当前结果顺序连续浏览与缩略图切换、图片适应/原始尺寸/缩放平移、音视频播放与倍速。

本机音视频可生成有界波形，配合时间输入、起止滑块和循环试听提取片段。波形只读取已关联的本机文件（2 GB、30 分钟以内，最多 8 秒处理），失败仍可使用时间标记。音轨可能包含口播和环境声，不提供人声分离。在线下载与音频提取在预览内选择参数，后台任务状态原位更新，完成后可查看目标库。

候选文件支持标签项、星级、备注及明确保存；切换或关闭保留本次窗口会话的未保存草稿（最多 40 项）。已入库条目沿用现有只读标记契约，来源面板保留许可、可复制路径与音频加工记录。桌面验收范围为默认窗口及 860×600 逻辑像素，不包含移动端、读屏或 200% 缩放。

### 2.14 抖音评论与快照

- 从搜索结果、收藏或同来源的入库素材打开预览，在“评论”页签按需读取；复用已连接的抖音官网会话，读取官网渲染的公开内容。
- 每次最多读取 60 条主评论，每页 10 条；展示昵称、正文、时间、可见点赞与作者标记，并支持展开本次已读取的回复。头像获取失败时使用昵称首字。
- “点赞优先”仅对已加载评论排序。“保存热门快照”从本次采样按点赞选取最多 20 条，包含已读取回复，不代表完整评论或平台热评排行。
- 快照按作品来源 URL 存在本机插件数据库中；在线作品与同来源的入库素材共用，重开详情优先读取已存快照，不依赖再次登录。暂不提供跨设备同步。
- 加载可取消；切换素材会忽略晚到响应。官网验证或网络失败时可重试，其他平台显示暂不支持，不尝试私有接口或验证码绕过。
