# 工作日志「AI 日程规划与工作安排」方案

> 配套文档：`docs/work-log-project-board-design.md`（项目状态与当前工作台）。
> 本文聚焦：在项目状态之上，增加可执行的工作项、预计耗时、每日/每周日程规划、AI 编排、计划与实际复盘，以及主流真实场景下的落地方式。

## 1. 目标与边界

### 1.1 要解决的问题

工作日志已经能回答：

- 过去做了什么。
- 每个项目投入了多少时间。
- 最近有哪些阻塞和下一步。

但还不能很好回答：

- 今天/本周应该先做什么。
- 每件事预计要多久，是否有足够时间。
- 会议、专注时间、缓冲时间如何安排。
- 临时插入紧急事项后，原计划受什么影响。
- 计划与实际差多少，下一次估算应该如何调整。
- 多个项目、多个截止日期同时存在时，如何取舍。

### 1.2 产品边界

这不是要替代 Jira、Linear、飞书项目、钉钉项目或完整日历系统，而是做一个**个人/小团队的本地工作规划层**：

- 本地优先，数据保存在工作日志库。
- 与现有工作日志、项目登记、AI 会话采集打通。
- 以「项目 → 工作项 → 时间块」三层模型组织。
- AI 负责建议、拆解、估算和解释；确定性调度器负责不冲突、不超容量。
- 计划必须可被用户接受、修改、推翻，不搞黑盒自动排程。

## 2. 三层模型

### 2.1 项目层

回答「做什么、为什么做、优先级、是否完成」。

- 项目状态：待开始 / 进行中 / 受阻 / 待验收 / 已完成 / 暂停。
- 优先级：P0 / P1 / P2 / P3。
- 目标、目标日期、里程碑、完成摘要。
- 最近活动、本周投入、风险提示。

### 2.2 工作项层

回答「具体做什么、预计多久、还剩多少」。

工作项是项目下可执行的最小规划单位，不等于完整任务管理系统：

- 标题、所属项目、功能/展项。
- 状态：待办 / 进行中 / 受阻 / 已完成 / 取消。
- 优先级、截止日期。
- 预计耗时、剩余耗时、实际耗时。
- 依赖关系（可选）。
- 来源：手工创建、项目下一步、日志 `next`、AI 拆解。
- 预估置信度：低 / 中 / 高。

### 2.3 日程层

回答「什么时候做、做多久、和会议是否冲突」。

- 固定日历事件：会议、评审、出差、个人事务。
- 计划时间块：专注块、会议、行政、休息、缓冲。
- 锁定块：AI 不允许移动的事件或用户锁定的专注块。
- 实际执行：开始/结束、实际分钟、被打断原因、是否完成。
- 计划版本：每次重排保留 revision 和原因。

### 2.4 三层关系

```text
项目（为什么做 / 优先级 / 截止）
  └─ 工作项（做什么 / 预计多久 / 剩余多少）
       └─ 时间块（什么时候做 / 做多久）
            └─ 实际日志（实际做了什么 / 花了多久）
```

工作日志条目通过 `project`、`feature`、时间窗口和显式 `work_item_id` 与工作项关联，形成计划与实际的闭环。

## 3. 主流实际场景

| 场景 | 典型痛点 | 方案 |
| --- | --- | --- |
| 多项目并行开发者 | 每件事都重要，频繁切换，计划被临时任务打断 | 今日聚焦最多 3 项；WIP 限制；P0/P1 排序；临时插入后一键重排并显示影响 |
| 会议密集的技术负责人 | 白天被会议切碎，没有完整专注时间 | 读取日历，保护 2 小时专注块；会议前后自动留准备/收尾缓冲；限制上下文切换 |
| 交付型项目经理 | 固定验收日期，剩余工作量不清，风险发现太晚 | 里程碑 + 剩余工时 + 倒排计划；容量不足时提前告警；建议缩范围/加资源/调整日期 |
| 多客户顾问/外包 | 客户优先级不同，计费与非计费工作混杂 | 客户/计费标签；按 SLA 和优先级排程；周利用率与计费工时统计 |
| 运维/支持岗位 | 紧急问题随时插入，计划经常失效 | 预留 20%-30% 中断缓冲；紧急队列；重排时只移动低优先级块 |
| 个人学习/副业 | 工作忙时长期搁置，缺少固定投入 | 固定学习块；最低周投入；连续未投入提醒；与项目目标绑定 |
| 跨天/大任务 | 任务太大，无法估算，容易拖 | AI 拆成 30-90 分钟可执行块；每天只排可完成部分；剩余工时滚动 |
| 估算经常不准 | 计划总是过满，实际做不完 | 历史实际/估算校准；P50/P80 区间；默认只承诺容量的 70%-80% |
| 频繁跨项目切换 | 每次切换都有上下文成本 | 每天最多 2-3 次主要上下文切换；同项目任务尽量连续排 |
| 远程/混合办公 | 会议、通勤、家庭事务穿插 | 支持工作日历、时区、全天事件、通勤/个人锁定块 |

## 4. 核心闭环

```text
早晨规划 → 白天执行 → 随时重排 → 收工复盘 → 估算校准 → 周计划 → 下一轮
```

### 4.1 早晨规划（3-5 分钟）

1. 读取项目状态、工作项、日历、最近日志、个人偏好。
2. AI 生成今日计划草稿：
   - 今日三件事。
   - 时间块安排。
   - 风险与取舍说明。
   - 需要用户确认的问题。
3. 确定性校验：不重叠、不超容量、依赖顺序、锁定块不被移动。
4. 用户接受或调整后提交为正式计划。

### 4.2 白天执行

- 点击「开始」进入专注块，记录开始时间。
- 遇到中断时选择：暂停、拆分、顺延、取消。
- 新任务插入时触发「重排预览」，显示哪些块被移动、哪些被放弃。
- 完成工作项后更新剩余工时，并可选写一条日志。

### 4.3 收工复盘（1-2 分钟）

- 对比计划与实际：
  - 完成了什么。
  - 哪些未完成，原因是什么。
  - 实际耗时与预计耗时差多少。
- 更新剩余工时。
- 生成明日建议（Top 3 + 需要提前处理的风险）。
- 可选自动生成日报。

### 4.4 每周复盘（15-20 分钟）

- 本周计划完成率、估算准确率、专注时长、会议占比。
- 各项目进展、阻塞、下周里程碑。
- 下周容量（会议、请假、出差）。
- AI 建议下周承诺项和取舍。
- 用户确认后生成周计划。

## 5. 数据模型

### 5.1 工作项 `work-items.json`

```json
{
  "schema_version": "work-log-work-items.v1",
  "updated_at": "2026-10-19T09:00:00+08:00",
  "items": [
    {
      "id": "wi-abc123",
      "project_id": "pj-abc123",
      "project": "项目看板",
      "feature": "AI 日程规划",
      "exhibit": "",
      "title": "实现每日计划生成",
      "status": "todo",
      "priority": "P1",
      "estimate_minutes": 90,
      "remaining_minutes": 90,
      "actual_minutes": 0,
      "estimate_confidence": "medium",
      "estimate_source": "historical",
      "due_date": "2026-10-24",
      "scheduled_for": "2026-10-19",
      "depends_on": [],
      "tags": ["planner", "backend"],
      "source": "project_next_step",
      "created_at": "2026-10-19T09:00:00+08:00",
      "updated_at": "2026-10-19T09:00:00+08:00",
      "completed_at": ""
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `status` | `todo` / `in_progress` / `blocked` / `done` / `cancelled` |
| `estimate_minutes` | 初始预计耗时 |
| `remaining_minutes` | 当前剩余耗时，复盘时更新 |
| `actual_minutes` | 从日志/专注记录归集的实际耗时 |
| `estimate_confidence` | `low` / `medium` / `high` |
| `estimate_source` | `manual` / `historical` / `ai` |
| `depends_on` | 前置工作项 ID |
| `source` | `manual` / `project_next_step` / `log_next` / `ai_split` |

### 5.3 日历事件 `calendar/events.json`

```json
{
  "schema_version": "work-log-calendar.v1",
  "updated_at": "2026-10-19T08:30:00+08:00",
  "events": [
    {
      "id": "evt-001",
      "source": "ics",
      "external_uid": "meeting-123@example.com",
      "title": "项目周会",
      "start": "2026-10-19T10:00:00+08:00",
      "end": "2026-10-19T11:00:00+08:00",
      "all_day": false,
      "busy": true,
      "locked": true,
      "location": "",
      "project_id": "pj-abc123",
      "privacy": "title"
    }
  ]
}
```

隐私模式：

- `title`：保留标题，用于会议准备和项目关联。
- `busy`：只保留忙闲，不保留标题，适合敏感日历。
- `hidden`：不导入该事件。

### 5.5 估算校准

不单独维护复杂模型，按项目/类型/来源聚合历史：

- `estimate_minutes` 与 `actual_minutes` 的比值。
- 样本量。
- P50 / P80 实际耗时。
- 最近 30/90 天趋势。

展示示例：

> 预计 90 分钟；同类任务历史中位数 75 分钟，P80 为 120 分钟；该项目整体实际比估算高 30%，建议预留 120 分钟。

## 6. AI 与确定性调度器分工

### 6.1 为什么不能只靠 AI 排程

纯 AI 排程容易出现：

- 时间重叠。
- 超过可用容量。
- 忽略会议和锁定块。
- 依赖顺序错误。
- 估算过于乐观。
- 每次生成结果不稳定。

### 6.2 推荐分工

| 环节 | 负责方 |
| --- | --- |
| 任务拆解 | AI |
| 优先级建议与取舍解释 | AI |
| 估算建议 | AI + 历史统计 |
| 日历理解、会议准备 | AI |
| 风险识别、自然语言说明 | AI |
| 时间块落位 | 确定性调度器 |
| 容量/重叠/依赖校验 | 确定性调度器 |
| 锁定块保护 | 确定性调度器 |
| 最终确认 | 用户 |

### 6.3 调度算法（确定性部分）

输入：

- 可用工作窗口。
- 固定会议和锁定块。
- 工作项优先级、截止日期、剩余耗时、依赖。
- 个人偏好：缓冲、最大专注块、上下文切换上限。

规则：

1. 先排 P0、临近截止、阻塞他人的工作项。
2. 按依赖拓扑顺序安排。
3. 超过 90 分钟的任务拆成多个块。
4. 每个专注块之间插入 10-15 分钟休息。
5. 保留 15%-25% 缓冲。
6. 每天最多 2-3 次主要上下文切换。
7. 同项目任务尽量连续。
8. 会议前后预留准备/收尾时间。
9. 超出容量时输出风险，而不是硬塞。
10. 不移动锁定块。

### 6.4 AI 输出契约

AI 只输出结构化建议，不直接写库：

```json
{
  "mode": "balanced",
  "focus_items": ["wi-1", "wi-2", "wi-3"],
  "blocks": [
    {
      "work_item_id": "wi-1",
      "start": "2026-10-19T09:30:00+08:00",
      "end": "2026-10-19T11:00:00+08:00",
      "kind": "focus",
      "rationale": "..."
    }
  ],
  "risks": [],
  "questions": [],
  "summary": "今天优先推进..."
}
```

之后必须经过：

`work-log.plan.validate` → 用户确认 → `work-log.plan.commit`

## 7. UI 方案

### 7.1 信息架构

建议把页签收敛为：

`工作台 | 计划 | 日志 | 项目`

- **工作台**：当前项目状态 + 今日计划摘要 + 风险。
- **计划**：日/周计划、时间块、AI 排程、容量。
- **日志**：日历回看、报告、工时表。
- **项目**：项目登记与项目详情。

原有「日历回看 / 报告 / 工时表」作为「日志」下的子视图，避免一级页签过多。

### 7.2 工作台

```text
┌──────────────────────────────────────────────────────────┐
│ 10 月 19 日 周一       今日可用 4.5h   已排 3.5h   [规划] │
├──────────────────────────────────────────────────────────┤
│ 现在该做：项目 A · 实现每日计划生成                      │
│ 09:30-11:00 · 预计 90m · 第 1/3 个专注块                  │
├──────────────────────────────────────────────────────────┤
│ 今日三件事                                               │
│ 1. [P0] 项目 A 修复登录问题        预计 90m  09:30       │
│ 2. [P1] 项目 B 方案评审准备        预计 60m  14:00       │
│ 3. [P1] 项目 C 验收问题处理        预计 45m  16:00       │
├──────────────────────────────────────────────────────────┤
│ 风险：项目 C 明天截止，剩余 3.5h，本周容量不足            │
│ 阻塞：项目 B 等待设计确认                                 │
└──────────────────────────────────────────────────────────┘
```

### 7.3 计划视图

日视图：

- 左侧：未排工作项，按优先级/截止日期排序。
- 中间：时间轴，显示会议、专注块、休息、缓冲。
- 右侧：AI 建议、风险、问题、重排按钮。
- 顶部：容量条（已排 / 可用 / 缓冲）。
- 底部：计划版本和变更记录。

周视图：

- 7 天列，显示每天容量、会议、关键里程碑。
- 点击某天进入日计划。
- 显示跨天任务和截止日期。
- 周容量超载高亮。

交互：

- 拖拽工作项到时间轴。
- 拖动时间块调整时间。
- 锁定/解锁时间块。
- 「AI 重新规划」保留锁定块。
- 「只排上午 / 只排 P0」等快捷模式。

### 7.4 复盘视图

- 计划 vs 实际对照表。
- 完成、部分完成、未开始、取消。
- 实际耗时、预计耗时、偏差。
- 未完成原因：被会议打断、估算不足、依赖阻塞、优先级变化、主动放弃。
- 明日 Top 3 建议。
- 一键生成日报。

### 7.5 工作项详情

- 标题、项目、功能、状态、优先级。
- 预计 / 剩余 / 实际耗时。
- 截止日期、依赖。
- 子步骤清单。
- 关联日志。
- 「开始专注」「拆解」「调整估算」「完成」。

## 8. 能力与工作流设计

### 8.1 插件能力

只读：

- `work-log.item.list`
- `work-log.plan.context`：聚合项目、工作项、日历、日志、偏好，供 AI 使用。
- `work-log.plan.read`
- `work-log.calendar.list`
- `work-log.planner.prefs.get`
- `work-log.plan.review`：计算计划与实际差异。

写入：

- `work-log.item.upsert`
- `work-log.item.update`
- `work-log.item.complete`
- `work-log.plan.validate`
- `work-log.plan.commit`
- `work-log.plan.replan`
- `work-log.calendar.import`
- `work-log.calendar.export`
- `work-log.planner.prefs.set`

原则：

- 插件不直接调用大模型。
- AI 能力由工作流 `himind.builtin` 提供。
- 插件负责确定性校验、存储和查询。

### 8.2 工作流

#### `daily-plan`

1. `PLAN-CONTEXT`：读取工作台、工作项、日历、偏好、最近日志。
2. `PLAN-AI`：AI 生成计划草稿和风险说明。
3. `PLAN-VALIDATE`：确定性校验。
4. `PLAN-COMMIT`：用户确认后写入。

#### `daily-review`

1. `REVIEW-CONTEXT`：读取今日计划和实际日志。
2. `REVIEW-AI`：分析偏差、原因、明日建议。
3. `REVIEW-SAVE`：更新剩余工时、记录复盘、可选生成日报。

可以并入现有 `daily-work-log`，作为收工后的可选段。

#### `weekly-plan`

1. 读取本周实际与估算准确率。
2. 读取下周会议和容量。
3. AI 提出下周承诺项和取舍。
4. 用户确认后生成周计划。

#### `replan`

触发条件：

- 新增 P0/紧急任务。
- 会议新增或取消。
- 估算严重超时。
- 出现阻塞。
- 用户主动要求。

输出：

- 变更前后对比。
- 被移动/取消的块。
- 影响说明。
- 新的风险。

## 9. 与现有工作日志的闭环

### 9.1 计划到日志

- 开始专注块时记录 `work_item_id`。
- 结束时写入实际分钟，可生成一条日志草稿。
- 完成工作项时，可选写入 `outcomes`、`next`。

### 9.2 日志到计划

- 日志里的 `next` 可以作为「建议工作项」。
- 用户点击采纳后生成工作项，不自动创建。
- 项目下一步清单可以批量转为工作项。

### 9.3 实际耗时归集

优先顺序：

1. 显式 `work_item_id` 关联。
2. 时间窗口 + 项目/功能匹配。
3. 用户手工确认。

AI 会话采集到的实测分钟可以直接用于估算校准，这是工作日志相比普通待办工具的优势。

### 9.4 会议自动记录

会议结束后可提示：

- 是否记录为工作日志（`category=会议`）。
- 预计时长和实际时长。
- 是否生成后续工作项。

默认不自动写入，避免噪声。

## 10. 估算、容量与优先级规则

### 10.1 估算

- 使用分钟，不使用故事点。
- 显示区间：预计 90 分钟，建议预留 120 分钟。
- 估算来源和置信度必须可见。
- 完成后记录偏差，用于后续校准。
- AI 不得凭空给出精确到个位数的估算，优先使用区间和历史中位数。

### 10.2 容量

- 日容量 = 工作时段 - 会议 - 休息 - 缓冲 - 行政。
- 默认只承诺 70%-80% 可用容量。
- 每日深度工作上限默认 4 小时。
- 每周容量按天汇总。
- 超载时显示「需要取舍」，不自动压缩所有任务。

### 10.3 优先级

排序参考：

1. P0/P1。
2. 截止日期临近。
3. 阻塞他人或阻塞验收。
4. 项目状态（受阻/待验收优先处理）。
5. 依赖关系。
6. 任务年龄（长期未推进）。
7. 预计耗时是否适合当前时间窗口。

AI 可以调整权重，但必须解释理由。

### 10.4 WIP 与专注

- 同时进行中的工作项建议不超过 2 个。
- 同一时间只允许 1 个专注块。
- 每天主要上下文切换不超过 3 次。
- 大任务必须拆分到可在 90 分钟内推进的粒度。

## 11. 日历集成

### 11.1 MVP：ICS

- 导入本地 `.ics` 文件。
- 支持重复事件、全天事件、时区。
- 只读导入，不直接修改外部日历。
- 可导出计划为 `.ics`，导入 Outlook / Google Calendar / 钉钉 / 飞书。

### 11.2 后续连接器

- Microsoft 365 / Outlook。
- Google Calendar。
- 钉钉日历。
- 飞书日历。
- 企业微信日程。

建议先做「单向导入忙闲 + 单向导出计划」，不要一开始做双向同步。双向同步需要处理冲突、重复事件、隐私和权限，复杂度高。

### 11.3 隐私

- 默认只读取忙闲和必要标题。
- 支持 `busy-only` 模式。
- 不把完整会议内容发送给云端模型。
- 本地优先；使用云端模型时只发送规划所需的最小字段。

## 12. 与工作台/项目看板的关系

现有 `daily-work-log` 已支持从工作台同步项目和展项：

- `business.project.list`
- `business.exhibit.list`

规划层建议：

- **读取**工作台的项目、展项、里程碑（如果可用）。
- **本地维护**个人工作项、优先级、估算和日程。
- **不默认回写**工作台状态，避免个人计划与团队状态冲突。
- 后续如需要双向同步，必须定义字段所有权和冲突解决策略。

## 13. 实施路线

### Phase 1：项目工作台

- `projects.json` v2。
- 项目状态、优先级、下一步、完成。
- 「工作台」页签。
- `work-log.project.board`、`work-log.project.work.update`。

### Phase 2：工作项与手工计划

- `work-items.json`。
- 工作项 CRUD、估算、剩余工时、依赖。
- 日计划文件、时间块、容量计算。
- 计划视图（先列表 + 简单时间轴，不做拖拽）。
- 计划与实际日志的基础关联。

### Phase 3：AI 日程规划

- `daily-plan` 工作流。
- `work-log.plan.context`、`validate`、`commit`。
- AI 生成今日三件事、时间块、风险、问题。
- 用户确认/修改/重排。
- 日报附计划完成情况。

### Phase 4：复盘与校准

- `daily-review`。
- 实际 vs 计划。
- 估算偏差统计。
- 剩余工时更新。
- 周计划与周复盘。

### Phase 5：日历与高级场景

- ICS 导入/导出。
- 会议准备/收尾块。
- 中断缓冲、上下文切换限制。
- 多客户/计费标签。
- 后续日历连接器。

## 14. 验收标准

Phase 2-4 完成后应满足：

- 每个进行中项目都有明确状态、优先级和下一步。
- 工作项有预计耗时和剩余耗时。
- 今日计划不超容量、不与会议冲突、保留缓冲。
- AI 生成的计划必须经过校验和用户确认。
- 临时插入任务后可重排，并显示影响。
- 收工时可对比计划与实际，更新剩余工时。
- 估算校准能给出历史依据，不是拍脑袋。
- 日志中的实测分钟可以归集到工作项。
- 周计划能看到容量、里程碑和风险。
- 所有数据本地保存，备份/恢复不丢计划。
- 旧日志和旧项目数据无需手工迁移。

## 15. 风险与取舍

| 风险 | 应对 |
| --- | --- |
| 计划过满，长期不可执行 | 默认 70%-80% 容量；缓冲；超载提示 |
| AI 估算不可信 | 历史校准 + 区间 + 置信度 + 用户确认 |
| 纯 AI 排程冲突 | 确定性调度器 + 校验器 |
| 计划频繁变动 | 版本化；重排原因；锁定块；限制每日重排次数 |
| 变成重型任务系统 | 只做项目/工作项/时间块三层；不引入复杂流程 |
| 日历隐私 | busy-only、本地优先、最小字段 |
| 双向同步复杂 | 先单向导入/导出 |
| 工作台状态冲突 | 本地计划优先；回写需明确策略 |
| 数据分散 | 全部放日志根目录，由 work-log 插件统一管理 |
| 用户不愿维护 | 自动从日志/项目下一步生成建议；一键采纳；复盘自动化 |

## 16. 推荐默认值

- 默认规划模式：均衡（保留 20% 缓冲）。
- 每日承诺上限：可用容量的 80%。
- 最大专注块：90 分钟。
- 每日深度工作上限：4 小时。
- 每日主要上下文切换：最多 3 次。
- 今日聚焦：最多 3 项。
- 同时进行中工作项：最多 2 个。
- 估算展示：P50 + 建议预留 P80。
- 优先级：P0-P3。
- 状态：待开始 / 进行中 / 受阻 / 待验收 / 已完成 / 暂停。
- 日历：先 ICS 单向导入 + 计划导出。
- AI：插件不直连模型，由 `himind.builtin` 工作流生成，插件校验后落库。

## 17. 结论

推荐把工作日志从「记录工具」升级为「记录 + 规划 + 复盘」的个人工作闭环：

```text
项目状态（做什么、优先级、是否完成）
  + 工作项（具体任务、预计耗时、剩余耗时）
  + 日程（会议、专注块、缓冲、容量）
  + AI（拆解、估算、排序、解释、重排）
  + 日志（实际投入、产出、阻塞、下一步）
  = 可持续的个人工作系统
```

关键不是让 AI 替用户排满日程，而是让 AI 帮用户：

- 看清当前最重要的 3 件事。
- 判断今天是否真的做得完。
- 在变化发生时快速重排并说明代价。
- 用真实日志校准下一次估算。
- 每周从「忙」回到「有进展」。
