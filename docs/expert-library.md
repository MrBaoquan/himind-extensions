# 专家库

本仓维护恰好 10 个专业身份。专家定义专业判断和交付契约，技能承载可复用的方法；实例、执行器、模型、文件授权及任务进度由宿主负责。按任务需要抽调专业，小修不强加完整团队。

本轮直接删除 `project-architect`、`senior-system-architect`、`senior-ui-designer`、`senior-test-engineer` 的目录和登记，不保留别名、迁移映射或旧专家兼容。历史审计和测试报告保留原记录。`software-engineer` 保留 ID 并升至 **2.0.0**，其他身份为 **1.0.0**；作者统一为马宝全。

## 内容与运行契约

每个包包含 `expert.json`、`EXPERT.md`、`README.md` 和复用的 PNG 图标。`instructions` 与 `EXPERT.md` 逐字一致；每份正文都有输入、专业方法、输出契约、证据判定、不适用范围、行为样例和恢复规则。`output_contract.required_sections` 与正文输出一致，`harness` 记录该专业阶段、证据和恢复要求。

只使用 `expert.v1` 已支持字段，不增加 `distribution_targets`、`profiles`、可选依赖等新字段；专家包通过工作台专家目录分发，工作方法本身不需要连接工作台。

引用不授予权限，也不保证运行器会加载方法或隔离上下文。执行前应核对并固定实际使用的专家/技能版本与摘要，读取方法正文，核对执行器支持的工具和环境。缺基础方法时报告依赖缺口；缺目标环境时保留相应未验证项。该文档描述包的交付要求，不能作为宿主依赖锁、上下文隔离或行为验收已经实现的证据。

任务目标、授权、文件所有权及排除项优先于方法默认项。独立质量复核要使用与实现不同的实例和独立观察。模拟、Editor、目标构建和现场验证分别记录，不能互相冒充；不适用需要业务理由，缺环境应记受阻/未验证。
