# 有界工程交付

## 输入与边界

输入目标/AC、工作区、允许写入文件、不可改项、工具与检查约束。先读 README 和本地规范、构建入口、依赖锁与工作区差异。已有授权足够就继续；仅当缺失决定性输入时阻塞相关动作，不把例行实现选择交回用户。

## 方法

1. 记录基线 commit 和相关未提交差异；未提交候选补充文件摘要及生成产物身份。将既有失败与本次新增失败区分，保护人工和并行任务修改。
2. 缺陷先记录触发步骤、预期/实际和根因；新功能先找到相邻实现及契约。只有变更需要时才调整依赖，不进行无关清理或大规模格式化。
3. 分成可回退的小步，每步写明确输出与验证。并行写按文件或模块分配唯一所有者；共享场景、Prefab、锁文件和 SVN 工作区串行，不能把目录不同当成可任意并行。
4. 实现正常、错误、取消和重复操作语义，沿用项目约定。跨接口变更同步调用方；数据变更同时提供检查及恢复办法。
5. 选择最小充分检查：行为逻辑做针对性回归，编译边界做构建，界面和引擎变化看目标渲染，设备副作用用对应实机方法。低影响文案改动可用差异审查，不为实现机械复制测试。
6. 在固定候选上记录实际命令、退出码、关键输出和环境。构建、截图或日志必须属于该候选；修改后仅重跑受影响证据，独立质量复核按任务要求另派实例。

## 输出与验收

交付行为变化、changed files、候选身份、运行/复现步骤、检查结果、未覆盖项与恢复步骤。范围内全部 AC 有结果，差异无越界、无误删既有修改，必要检查通过才标实现就绪。未运行的检查保持未验证；实现就绪不等于独立验收或发布。

## 受阻与恢复

环境缺依赖先报告实际缺口，继续可完成的源码与静态工作；未经授权不安装或改宿主配置。新增失败定位到最近一小步，修复或只撤销自己的那部分差异。发现并行文件冲突暂停对应文件，保留双方内容交给整合者，不用整库 reset 或清理消除冲突。
