# 架构决策方法

## 输入与边界

输入需求/AC、当前模块与部署拓扑、数据所有权、规模和延迟约束、故障记录、工程限制。事实附源码或测量来源。小范围局部修复无需重画全系统；没有跨边界变化时只记录局部判断。

## 方法

1. 将“可靠、可扩展”等词改写为质量属性场景：刺激源、运行环境、受影响组件、响应和量化阈值。先记录当前基线和未知项。
2. 画上下文和数据流：每份可变数据一个权威所有者；标出信任边界、同步/异步、事务边界、调用方向和故障传播。
3. 至少比较保留现状的最小修补与一个可行替代方案；按目标质量属性、实现及运维成本、可逆性评价。约束已唯一确定的选择写排除理由，不编造伪方案。
4. 写接口契约：输入输出、版本、错误、取消、超时、重试、幂等键、并发及一致性语义。检查超时后重试会不会重复副作用，部分成功如何被调用方识别。
5. 以 ADR 记录背景、决策、备选、得失、成立条件和重审触发。将高风险假设转成有通过阈值的最小实验；没有实验结果就是未验证。
6. 迁移按可检查的小步给出旧/新状态、数据校验、观测指标、停走阈值和恢复动作。代码回滚与数据恢复分别设计；不可逆写入说明备份、前向修复及恢复演练方法。

## 输出与验收

交付边界/数据流、质量属性表、接口契约、ADR、迁移与恢复表、实验结果或计划。每个关键决策关联需求、证据和验证项。

通过条件：状态所有权无冲突；关键错误/超时/重复请求均有确定行为；最高风险假设有实测结果或显式阻塞；每个迁移阶段有停走条件和可执行恢复。没有数据恢复证据时不能宣称迁移可回滚。

## 受阻与恢复

观测与假设冲突时撤回相关结论，缩小实验并更新 ADR。接口双方认知不一致时冻结争议接口，独立模块可继续。迁移失败先停止新写入扩散、保护现场和备份，再执行已验证的恢复或前向修复；不临时创造第二个数据权威源。
