# 设备协议与恢复

## 输入与边界

输入设备型号/固件/拓扑、协议原文、地址与通道表、单位/量程、更新频率、反馈方式、停止及现场操作约束。设备型号、通道或安全参数未知时只做协议分析/模拟，不猜测参数下发。软件预检不能替代机械、电气或现场安全验收。

## 方法

1. 建设备身份和独占表：设备标识、连接端点、占用者、配置版本和操作范围。连接成功只证明传输层可达；核对握手及身份后再认定连接到目标设备。
2. 协议表定义帧边界、长度、字节序、校验、序号、单位换算、量程、发送/应答/完成含义、超时、重试与幂等。ACK 与实际执行完成分开；无反馈设备记录无法闭环确认的限制。
3. 状态至少覆盖断开、握手、就绪、执行、故障/停止、恢复。定义谁允许发送、连接代次、指令过期、断连队列处理和停止优先级；重连不得重放过期运动指令。
4. 先用无副作用样本/模拟验证分包粘包、坏校验、越界值、乱序/重复/丢帧和超时，记录每种输入的预期响应及实际日志。对不可幂等动作不得盲目重发。
5. 真实联调在已授权条件和现场操作约束内串行执行：先确认停止路径，再测试有限范围动作及反馈；注入断连/重启等故障前确认不会破坏现场。需要外部监护或物理操作而条件未满足时只阻塞该项。
6. 工程使用 IOStudio 时加载仓内「IOStudio 调试助手」核对实际安装、生效设备表、动作与通道；涉及视频动作再选「视频动作编排」。这些是可选适配，不把 IOStudio 或媒体插件写成通用方法的必需依赖。

## 输出与验收

交付设备/版本/通道表、协议与状态契约、配置差异、模拟记录、实机日志/反馈、恢复步骤和限制。通过条件：约定量程/单位正确；超时停止行为符合现场契约；重连不重复旧指令；实机反馈在约定时限内达到目标。记录阈值、测量点和测试次数，模拟绿灯或 ACK 均不能单独作为实机通过证据。

## 受阻与恢复

身份/量程不符立即停止下发，保留原始报文与配置；断连清理待发队列，恢复须重新握手和核对设备状态。异常优先执行已验证停止路径，保留现场给设备负责人，不临时扩大行程或修改联锁。无真实设备时交付模拟证据及明确的现场待验项。
