# 实时交互开发

## 输入与边界

读取引擎/Editor 精确版本、依赖锁、渲染管线、目标平台/分辨率/输入设备、场景与存档约束、帧率/内存预算。Unity 读 ProjectVersion 与 Packages，其他引擎读对应 manifest。未使用 UNIHper 的工程不引入其基类、Manager 或包。

## 方法

1. 确认工具连接的是目标工程和匹配版本，检查编译及导入状态；禁止用另一版本 Editor 打开并升级工程。共享 Editor、场景、Prefab、导入缓存同一时间一个写入者，遵守项目 VCS 锁定规则。
2. 建状态与所有权表：启动、进入、运行、暂停、退出、释放；每项订阅、异步任务、资源句柄和输入监听都指定清理位置。重复进入不能重复注册，销毁后异步结果不能回写失效对象。
3. 输入映射到领域动作，处理去抖、触摸/指针穿透、焦点丢失、同帧事件优先级。游戏时间、真实时间、暂停与固定物理步长分别定义，不能依赖某台机器帧率。
4. 场景和资源按项目管线加载/卸载，验证缺失资源、加载取消和切换失败。持久状态与场景对象分离；存档明确格式版本、写入完整性、损坏恢复和升级策略。
5. 将 FPS 换成毫秒预算 1000/FPS，在同一目标硬件、内容和采样窗口测 CPU/GPU 帧时、p95/p99、GC 与峰值内存；首帧/切场单独记录。Editor FPS 不能替代目标构建测量。
6. 按改动选逻辑测试、引擎场景测试和目标构建，验证重复进入/退出、暂停恢复、输入及存档。UNIHper 已在工程中实际使用时，加载仓内「UNIHper 开发助手」补充框架生命周期和工具就绪规则；其缺失仅影响该框架分支。

## 输出与验收

交付候选身份、状态/资源所有权、修改与构建步骤、目标包及性能记录、未覆盖项。通过条件：场景循环无新增异常和悬挂订阅，资源增长在约定循环次数内收敛，存档可恢复，目标构建核心路径及约定性能阈值通过。采样次数、时长和容差先记录；不能仅凭 Editor 正常声称部署就绪。

## 受阻与恢复

无 Editor/许可证/目标机时继续可独立完成的逻辑和规格，明确缺失证据。导入或编译失败先保留日志、定位本次改动，不删全项目缓存掩盖问题。场景切换失败回到可控状态，保留持久数据，修复后重跑完整进入/退出及目标构建路径。
