# 异步任务

任何能力返回 `status: pending` 与 `task_id` 时，停在当前业务步骤。

## 主动轮询

仅登录/授权这类阻塞后续步骤的任务：先提醒用户扫码或确认，再调用 `wechat.miniprogram.devtools.task.get`，每次最多等待 10–30 秒，最多轮询 10 次。只有 `success` 才继续。

## 不主动轮询

上传、删除、云写、预览确认等：提醒用户在微信开发者工具内确认，记录 `task_id` 与最后状态，结束本轮。

## 恢复

用户回来继续或准备执行相同操作时，先用旧 `task_id` 查询：

| 旧状态 | 处理 |
|---|---|
| pending | 不得重发；继续等待或再查一次 |
| success | 原操作已成功，不得重发 |
| failed | 用户明确要求时才重试 |
| cancelled / expired | 不自动重发 |
| 状态不明 | 不重发可能产生副作用的操作 |

`pending` 不是失败，不得因为未轮询完而重新发起写操作。
