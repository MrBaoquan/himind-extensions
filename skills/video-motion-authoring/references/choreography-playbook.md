# 动作编排方法：从画面行为到平台体感

本方法用于把视频的**主叙事行为**转换为设备可执行的动作意图。目标不是逐帧复刻画面，而是让观众感受到画面所表达的升力、下沉、冲击、速度、环境和情绪。

## 1. 三层产物

必须按顺序产出：

```text
视频/音频证据
  → behavior-timeline.json   发生了什么、何时发生、置信度多少
  → motion-intent.json       观众应该感受到什么
  → ShowSpec / .motion       在当前设备上如何实现
```

禁止由低层信号直接跳到关键帧。每一段动作都应能追溯到行为时间线和设备能力。

## 2. 全景与主视觉

等距柱状/球幕影片先确定“主观看前向”，再进行画面分析：

- 使用 `media.toolkit.video.project` 展开固定前向视图。
- 记录 `yaw_deg`、`pitch_deg`、`h_fov_deg`、`v_fov_deg`。
- 全景里的左/右移动不等于平台 roll/sway；先判断主叙事运动方向。
- 如果观众可自由转头，平台动作跟随主叙事，不跟随观众视线。

## 3. 失重与姿态语法

Heave 类设备的失重感不靠小幅正弦，而靠以下序列组合：

```text
准备 → 快速上升/蓄势 → 短暂停留 → 快速下降 → 回弹 → 恢复
```

设备只有 Heave 时，重点使用：

- `lift`：快速上升或持续抬升
- `float`：高位停留、缓慢回落
- `drop`：短时间大幅下降
- `rebound`：下降后的回弹
- `settle`：分段衰减到中性位

避免：

- 持续 0.1–0.2 幅度的低幅正弦铺满整段
- 每个镜头都配同一种动作
- 把全景画面横向运动直接当平台方向变化
- 无回弹的硬阶跃

### 3.1 待机循环与飞行底噪

IOStudio 的 `idle` 是**空窗兜底**：轨道在 clip 内时直接返回 clip 求值，不读取 idle。因此：

- 一整段 long preset 内部的平坦区，idle 无法填充；
- 只有 cue 之间、cue 之前或 cue 之后的空窗才会使用 idle；
- 事件驱动的动作若切成短 clip，可以用 idle 填缝，但周期循环容易重复，通常不如为整段创作非周期飞行底噪。

推荐结构：

```text
全段 clip
  事件峰值：抬升 → 停留 → 下降 → 回弹
  事件间：低幅、非周期的飞行底噪
全段 clip 之外：idle 兜底
```

飞行底噪的幅度应明显低于事件峰值，但必须在任意 3 秒窗口里产生可感知变化。片尾复位和特效关闭窗口除外。

## 4. 片尾复位

动作结束不是最后一个动作关键帧，而是一个独立安全阶段：

```text
最后一个剧情事件 → 关闭全部环境特效 → Heave 复位 → 中性保持到片尾
```

Heave 必须回到设备 profile 的 `neutral`；风机、水、热风、震动、香氛不得在节目结束后继续开启。若设备表 SlewRate 加高，复位仍应优先使用受控斜率，而不是直接跳到 0。

## 5. 强度三档

同一片长、同一事件时点、同一动作结构，生成三档供现场比较：

| 档位 | 用途 | 原则 |
| --- | --- | --- |
| gentle | 首次现场测试 | 降低峰值和震动密度，但不删事件 |
| normal | 推荐主用 | 完整表达动作节拍和持续环境 |
| intense | 前两档通过后 | 提高峰值、下降速度和环境氛围，不改变事件时点 |

变体只改变可控参数：

- Heave 偏差幅度
- 上升/下降斜率
- 震动门控密度
- 风机风速档位
- 环境特效开窗时长

不应改变：段落边界、关键事件时刻、设备安全联锁。

## 6. 环境动作

### 风机

- 设备表为 bool 时只能开/关。
- 设备表为 float 且 `engineering_range=100` 时，门控 level `0.45` → 45%。
- 固定档位优先；不要逐帧连续 ramp，避免高频 UDP。
- 风速按场景变化：自由飞行、高速、峡谷、水面和终章应高于静态/对白段。

### 香氛

- 香氛是氛围辅助，不是动作主体。
- 只在有明显环境语义的段落开窗，例如雪林、木屋、水段、终章。
- 门控应短而清晰，并和镜头/事件时间点对齐。
- 没有香氛设备时直接跳过，不影响主流程。

### 其他环境

- 水、热风、震动、灯光必须从设备声明中取；不存在就降级并在摘要说明。
- 不要把 gate 类环境动作写成 pose preset。

## 7. 编排质量门槛

每个动作段落至少检查：

- 是否有明确的 `behavior` 和证据时间点
- 是否选择了动作家族，而不是只写了数值
- 高能段落是否达到目标强度档位的峰值
- 相邻 cue 的值和速度是否连续
- 是否存在整段低幅、无事件、无变化的“平缓噪声”
- 风机/香氛/水/震动是否有明确的开关语义
- 所有通道是否来自设备声明
- `iostudio.motion.plan` / `iostudio.motion.validate` / `iostudio.motion.tracks` 是否通过

建议的低层检查：

- `peak_heave`：该段动作峰值
- `dynamic_range`：该段最大值与基准值差
- `active_ratio`：非中性状态时间占比
- `event_alignment`：动作峰值对应的画面/声音证据
- `continuity_gap`：相邻 cue 的值跳变

这些指标不替代人工体感，但可以阻止“全片看起来都在动、实际上没有戏剧起伏”的编排。

## 8. 现场反馈闭环

现场按 gentle → normal → intense 顺序验证，每个版本回中复位。记录：

- 动作同步 1–5
- 失重感 1–5
- 舒适度 1–5
- 疲劳度 1–5
- 风机氛围 1–5
- 香氛时点是否自然
- 机械风险 1–5
- 需修改的时间段和原因

反馈只修改对应时间段的动作意图和参数；不要直接手改最终 `.motion`，否则下一轮无法复现。

## 9. 常见失败

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 大部分片段太平缓 | 只用了低幅正弦/模板 | 重建失重序列，增加 drop/rebound，检查强度档位 |
| 画面和动作不像 | 把 2D/全景拼接错，或没看主视觉 | 用主前向视图和 1s 分镜复核 |
| 动作持续但无冲击 | 关键事件没有对应峰值 | 用 audio/scene 峰值和画面证据对齐 |
| 风机开了但氛围不足 | 风机被当 bool 或风速过低 | 核对 float 轨、engineering_range 和门控 level |
| 香氛一直开 | 门控窗口过长 | 改为短窗口、和场景转场对齐 |
| 动作结束仍在动/吹风 | 没有片尾复位阶段 | 提前关闭全部 gate，Heave 回 neutral 并保持 |
| 现场只能凭感觉调 | 没有中间产物和指标 | 保存 behavior timeline、intent 和分档参数 |

## 10. 边界

AI 负责粗排、语义判断和不确定性标注；确定性代码负责时间量化、曲线包络、通道映射、限速和连续性。任何涉及物理动作的 `.motion` 都必须经过 IOStudio 预检和人工现场确认。
