# 界面无障碍

把「界面要能被所有人操作」落成可运行、可复验的实现。判定基线是数值和条款，不是偏好；验收对象是辅助技术实际读到的无障碍树，不是源码里看起来正确的属性。

## 触发边界

适用：

- 为组件或页面实现语义角色、键盘路径、焦点管理与读屏标签。
- 排查「键盘走不通」「焦点跑掉」「读屏念不出来」「只靠颜色表达状态」这类具体问题。
- 准备无障碍验收，需要按条款列出未达标项与修复方案。
- 桌面客户端与移动端需要映射到各自平台的无障碍接口。

不适用：

- 只要对比度、目标尺寸这类数值阈值的完整清单：先看「软件界面规范」的无障碍基线表，本技能不重抄。
- 只要视觉精致度、间距节奏、动效手感：用「界面工艺细节」。
- 从零生成设计系统、选风格配色字体：用「界面设计助手」。

## 第一原则

1. **语义优先于实现**：能用原生元素就不用自定义角色。按钮写成 `<button>`，链接用 `<a href>`，标题用真实层级。自定义角色要同时接管它的全部键盘语义和状态通知，只贴 `role` 是负债。
2. **按无障碍树验收**：判定依据是辅助技术读到的名称、角色、状态、关系，不是 DOM 里有哪些属性。写了 `aria-label` 但被内层文本覆盖、或者元素本身不可聚焦，等于没写。
3. **键盘与指针等价**：凡是能用指针完成的操作，都必须能用键盘完成；凡是多指手势或拖拽才能完成的操作，都必须有单击或键盘替代路径。
4. **状态不只靠颜色**：选中、出错、必填、离线等状态至少叠加一种非颜色的信息（文字、形状、图标、位置）。
5. **动效受系统偏好约束**：`prefers-reduced-motion` 为减时，位移与缩放必须停用，只保留不超过 0.2 秒的透明度过渡。
6. **自动检查只是下限**：语法扫描与对比度工具能覆盖的只是一部分；键盘走查与读屏实听必须人工完成。没做过就是未验证，不是通过。
7. **不谎报合规**：只写实际验证过的层级（A / AA）与范围（哪些页面、哪些浏览器与读屏组合）。未测的写明未测。

## 数值基线

以下阈值是本技能的实现判据；与「软件界面规范」的基线表一致，那里给的是审查口径，这里给的是实现口径。

| 约束 | 阈值 | 依据 |
| --- | --- | --- |
| 正文文本对比度 | ≥ 4.5:1 | WCAG 2.2 1.4.3 |
| 大号文本对比度（≥ 18pt，或 ≥ 14pt 粗体） | ≥ 3:1 | WCAG 2.2 1.4.3 |
| 非文本对比度（图标、边框、图形、状态点） | ≥ 3:1 | WCAG 2.2 1.4.11 |
| 目标尺寸 | ≥ 24×24 CSS px；触控推荐 ≥ 44×44 | WCAG 2.2 2.5.8 |
| 焦点可见 | 全部可聚焦元素有可见焦点指示，且不被遮挡 | WCAG 2.2 2.4.7 / 2.4.11（AA） |
| 焦点指示对比 | 指示器与相邻颜色 ≥ 3:1 | WCAG 2.2 1.4.11（AA） |
| 焦点指示面积（增强） | ≥ 2 CSS px 厚周长，且与未聚焦状态对比 ≥ 3:1 | WCAG 2.2 2.4.13（AAA，按目标等级选用） |
| 文本放大 | 200% 不丢内容、不需横向滚动 | WCAG 2.2 1.4.4 |
| 重排 | 320 CSS px 宽或 400% 缩放不出现二维滚动 | WCAG 2.2 1.4.10 |
| 文本间距覆盖 | 行高 1.5、段距 2em、字距 0.12em、词距 0.16em 时内容不截断 | WCAG 2.2 1.4.12 |
| 指针替代 | 拖动、多指、路径手势有单击或键盘等价 | WCAG 2.2 2.5.1 / 2.5.7 |

## Web 实现配方

每个配方给的是「必须同时成立的条件」，少一条都不算完成。

### 按钮与链接

- 触发动作的用 `<button type="button">`，导航到别的地址的用 `<a href>`；两者不可互换，读屏与右键菜单行为依赖这个区分。
- 只有图标的按钮必须有无障碍名称：优先可见文本，其次 `aria-label`，不要同时给两者造成重复朗读。
- 禁用状态优先用组件自身的禁用表达；只能用 `aria-disabled="true"` 时，必须自行拦截点击与键盘触发，并说明原因。

### 自定义下拉 / 组合框

- 触发器：`role="combobox"`、`aria-expanded`、`aria-controls` 指向列表 id。
- 列表：`role="listbox"`，每项 `role="option"` 带 `aria-selected`。
- 键盘：`ArrowDown/ArrowUp` 移动、`Home/End` 到首末、`Enter` 选中、`Esc` 关闭并归还焦点、输入时高亮项用 `aria-activedescendant` 指向当前项，而不是移动 DOM 焦点。
- 关闭后焦点回到触发器；点击外部关闭不能吞掉焦点。

### 对话框

- 打开时焦点进入对话框内第一个可交互元素（或标题），并把焦点限制在内部循环。
- `Esc` 关闭；关闭后焦点回到触发它的元素，而不是回到页面顶部。
- 容器 `role="dialog"` 加 `aria-modal="true"`，并有无障碍名称（`aria-labelledby` 指向标题）。
- 背景内容用 `inert` 或等价手段真正移出无障碍树，不只是视觉遮罩。

### 页签

- 容器 `role="tablist"`，每个页签 `role="tab"` 带 `aria-selected` 与 `aria-controls`，面板 `role="tabpanel"` 带 `aria-labelledby`。
- 键盘：`ArrowLeft/ArrowRight` 在页签间移动（水平）、`Home/End` 到首末，`Tab` 只在页签列表与面板之间跳。
- 只有当前页签在 Tab 序列里（roving tabindex）。

### 表单错误

- 每个控件有关联标签：`<label for>` 或 `aria-labelledby`；占位符不能替代标签。
- 出错时同时设置 `aria-invalid="true"` 与 `aria-describedby` 指向错误文本 id，错误文本本身可被读屏读到。
- 提交失败后在表单顶部给错误摘要，摘要项链接到对应字段，并把焦点移到摘要。
- 错误文案说清发生了什么、影响什么、下一步怎么做；不指责用户，不暴露内部错误码，但保留可复制的诊断标识。

### 动态内容

- 状态提示、异步结果、行数变化用 `aria-live="polite"`；打断性的严重错误用 `assertive`，但要克制——频繁播报本身是干扰。
- 加载中不要只转圈：给可读的状态文本，并说明能否取消。
- 列表虚拟滚动时，滚动容器要有角色与名称，且新加入的内容变化可被感知。

### 结构

- 每个页面一个 `h1`，标题层级连续，不跳级。
- 提供「跳到主内容」链接，且在获得焦点时可见。
- 表格有 `th`（必要时 `scope`）与 `caption`；纯布局不用表格。
- 图标是装饰时 `aria-hidden="true"`；承载信息时给等价文本。
- 不用 `tabindex` 大于 0 制造自定义顺序，DOM 顺序即焦点顺序。

## 桌面客户端

Windows 桌面（WPF / WinUI / WinForms / Avalonia）与 Unity 运行时界面：

- 每个可交互控件有 UIA 名称、角色与状态；自绘控件要实现对应 UIA 提供程序，不能只有鼠标命中区。
- 尊重系统高对比度主题：不写死前景背景色组合，跟随系统主题取值，并在高对比度下复验一次。
- 键盘：所有命令有可发现的快捷键路径；菜单与工具栏提供助记键；焦点顺序与视觉顺序一致，焦点框在深色与高对比度下都可见。
- 高 DPI：使用逻辑像素与多档位图标，200% 缩放下不重叠、不截断。
- 不用颜色区分选中与未选中的列表项，加图标或字重变化。

## 移动端映射

- iOS：`accessibilityLabel`、`accessibilityHint`、`accessibilityTraits` 与语义角色一致；可交互元素默认可聚焦，装饰元素 `isAccessibilityElement = false`；支持动态字体缩放。
- Android：`contentDescription` 承载含义而非外观；用 Compose `semantics` / 原生 `AccessibilityNodeInfo` 暴露角色与状态；支持字体缩放至 200% 不破版。
- 触控目标按平台阈值（iOS 44×44 pt、Android 48×48 dp），不为「更紧凑」而缩小。

## 审计流程

1. **定范围**：页面清单、目标等级（A / AA）、要覆盖的浏览器与读屏组合、平台版本。范围写进报告开头。
2. **静态检查**：语义结构、标签关联、角色与状态属性、图片替代文本。这一层可以借助工具与代码检索。
3. **数值检查**：对比度、非文本对比度、目标尺寸、放大与重排行为。装了「界面设计助手」的依赖插件时，可以用它的令牌校验能力取对比度与硬编码颜色问题；没装就按上表逐项手算，并在报告里写明用的是手算。
4. **键盘走查**：只用键盘完成核心任务，记录 Tab 顺序、焦点是否可见、对话框焦点归还、是否有键盘陷阱。
5. **读屏实听**：至少一种读屏（Web：NVDA 或 VoiceOver；桌面：讲述人；移动：VoiceOver / TalkBack）走一遍主流程，记录实际播报内容与预期差异。
6. **主题与偏好**：深浅色各核对一次对比度；开启减少动效后确认位移与缩放停止；高对比度模式下确认可读。
7. **回归**：改完在相同条件下复跑受影响的步骤，并确认修复没有在别处引入新问题。

## 报告格式

按问题逐条给，不按条款逐条给——一个条款可能在多处被违反，一处违反也可能同时踩多条。

| 字段 | 要求 |
| --- | --- |
| 编号 | 稳定编号，修复后仍可引用 |
| 现象 | 用户可感知的行为，不写「aria 属性缺失」这类实现断言 |
| 复现路径 | 具体页面、控件、键序或读屏操作步骤 |
| 证据 | 截图、选择器、读屏播报原文、对比度实测值 |
| 条款 | 规范名 + 条款号；无对应条款时说明来自目标产品自有规范 |
| 严重度 | 阻断（核心任务不可完成） / 严重（有绕行但成本高） / 一般（可用性受损） / 建议 |
| 修复方案 | 精确到文件与元素，写明要改的属性与行为 |
| 验收标准 | 可复验的判定条件，例如「键盘可从触发器打开列表并按 Esc 关闭，关闭后焦点回到触发器」 |

样本：

```text
#3 现象：打开设置对话框后用键盘关闭，焦点回到页面顶部，用户需重新走 20 次 Tab 才能回到原位置。
    复现：工作台 → 设置 → 键盘按 Esc。
    证据：焦点落在 body；截图 shot-03.png。
    条款：WCAG 2.2 2.4.3 焦点顺序。
    严重度：严重。
    修复：对话框关闭时记录 opener 元素并在 animate 完成后 focus()。
    验收：Esc 关闭后 document.activeElement 等于打开按钮。
```

## 与其它技能的分工

- 阈值清单与整体界面质量审查：先看「软件界面规范」七个审查方向里的无障碍方向，本技能负责把它落成实现。
- 视觉精致度、间距与动效手感：用「界面工艺细节」。
- 生成设计系统与配色字体：用「界面设计助手」；它负责初稿，本技能负责验收初稿是否可访问。

## 安全与边界

- 不读取或传递 Token、Cookie、私钥与凭据。
- 不访问任意 URL，不安装依赖，不修改工作区外文件。
- 需要写入时只改与本次无障碍问题相关的文件，不顺手重排无关样式。
