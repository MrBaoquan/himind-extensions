# 客户端能力探测与降级

目标：同一套协议在任何 AI 客户端都能跑，靠「探测实际能力 + 降级行为」，不靠客户端名字。

## 1. 探测项（每任务一次，写入 state.capabilities）

| 能力 | 判定方法 | 缺失时的影响 |
|---|---|---|
| `file_io` | 能否读、写、改工作区文件 | 缺失则本技能不可用，直接说明 |
| `shell` | 能否执行命令并拿到输出 | 验证退化为文件断言与人工确认 |
| `auto_continue` | 是否存在会话级目标、循环或自动继续机制 | 决定能否用 L1，否则用 L2 |
| `background_job` | 能否提交长时任务并轮询状态 | 长时操作改为拆轮同步执行 |
| `subagent` | 能否派生独立上下文执行子任务 | 可选；评审轮可借它隔离视角 |
| `todo_tool` | 是否有内置任务清单工具 | 可选；状态仍以状态文件为准 |

判定顺序：看可用工具与实际行为，不看客户端名称。探测结果只用于选档与降级，不作为对外能力声明。

## 2. 三档行为

**L1 自动续跑**（有会话级目标或循环机制）

- 每轮结束若未命中停止规则，直接进入下一轮，不再等用户输入。
- 只在四种情况打断用户：需要决策的阻塞、需要超授权、目标矛盾、不可逆风险。
- 仍要按里程碑汇报，避免长时间无输出。

**L2 单指令续跑**（默认，大多数客户端）

- 单次响应内尽量推进多轮，但守住单轮上限与上下文预算。
- 响应结束输出续跑块（模板见 `templates.md` 第 7 节）。
- 明确告知用户：跨响应需要一句「继续长任务 <task-id>」，不要假装仍在后台运行。

**L3 交接恢复**（新会话、上下文已压缩、换了客户端）

- 依次读 `handoff.md`、`state.json`、`task.md` 验收段。
- 先复述当前轮次与下一步，再继续，避免重复已完成工作。
- 若状态与现状不符，以证据为准修正后再推进。

能力在执行中变化（例如换了客户端）时重新探测并更新 `capabilities`，按新档位继续，并在 `progress.md` 记一条档位变更。

## 3. 没有命令执行能力时怎么验证

1. 文件断言：读取目标文件，核对约定内容或结构。
2. 静态检查替代：用客户端自带的搜索工具检查关键符号、配置项。
3. 人工确认：写入交付报告的「人工项」，不得自判通过。
4. 缩小任务：把需要命令验证的部分拆成独立任务，等有命令能力的会话再接续。

## 4. 有后台作业能力时

- 长时执行（构建、转码、批量抓取）提交为后台作业，记录作业 ID 到 `state.json`。
- 每轮只查状态，不阻塞等待；查不到就继续做可并行的前置工作。
- 作业失败时把关键输出落 `evidence/`，再决定重试或换方案。

## 5. 跨平台命令写法

优先用客户端自带的文件、搜索、执行工具；必须写命令时给两种写法：

| 目的 | POSIX | PowerShell |
|---|---|---|
| 判断文件存在 | `test -f <path>` | `Test-Path <path>` |
| 搜索文本 | `grep -n "<文本>" <path>` | `Select-String -Path <path> -Pattern "<文本>"` |
| 列目录 | `ls -la <dir>` | `Get-ChildItem <dir> -Force` |
| 看退出码 | `echo $?` | `$LASTEXITCODE` |

不要假设有 bash；不要把绝对用户目录写进契约或状态文件，用工作区相对路径。

## 6. 续跑与控制的常用说法

| 用户说 | 技能行为 |
|---|---|
| `继续长任务 <task-id>` / `继续上次的长任务` | 走 L3 恢复，先复述再推进 |
| `汇报进度` | 只读状态，输出里程碑摘要与验收进度 |
| `暂停长任务 <task-id>` | 置 `paused`，刷新交接卡 |
| `结束长任务 <task-id>` | 置 `stopped` 或 `done`，输出停止报告 |

## 7. 通用注意

- 客户端可能压缩或丢弃上下文：状态文件优先，对话只作线索。
- 客户端可能默认不自动继续：输出续跑块，不要假装继续。
- 工具名称各不相同：统一抽象为「读 / 写 / 改 / 搜索 / 执行 / 派生子任务」，不写死工具名。
- 不确定客户端是否有某能力时：先做一次小探测（读一个文件、跑一条无害命令），按结果选档，不要猜。
