# 长任务推进助手

把「已经聊清楚的事」变成「能自己做完的事」：先承接上下文形成**任务契约**，等用户确认后，按可验证轮次持续实施，并在会话中断、上下文被压缩或更换 AI 客户端后，从状态文件恢复继续。

## 适用与边界

在以下情况使用：

- 用户与你多轮讨论后说「整理成任务」「就这么办」「开始做」。
- 任务跨多轮、跨会话，单次响应做不完。
- 用户要求「确认后你自己推进，别每步都问我」。
- 用户说「继续上次的长任务」。

不要用于：

- 一两步就能做完的小事——直接做。
- 纯讨论、方案还没收敛——继续讨论，不要立项。
- 路径完全固定、需要审批和交付物的流程——交给 Workflow。
- 真正长时间的外部执行（转码、抓取、构建）——交给后台作业或插件能力，本技能只负责调度与记录。

## 三个阶段

```text
收敛立项（只读） → 确认门 → 自主执行（轮次推进） → 交付报告
                        ↑                              │
                        └────── 接续（新会话/换客户端）──┘
```

**立项轮禁止执行**：只读上下文、只产出契约，不修改业务文件，不运行会改变状态的命令。

## 状态目录

全部状态放在 `<工作区>/.himind/long-tasks/<task-id>/`。跨会话、跨客户端都以这些文件为准，不依赖对话历史。

| 文件 | 用途 | 约束 |
|---|---|---|
| `task.md` | 目标、验收、范围与非目标、已决、未决假设、授权、预算 | ≤80 行，唯一事实源 |
| `state.json` | 阶段、轮次、下一步、阻塞、证据索引、能力探测 | ≤60 行 |
| `progress.md` | 每轮一条：目标/动作/证据/结果/下一步；每 5 轮压缩 | 只追加 |
| `decisions.md` | 执行期新决策及理由，防止下个会话重新讨论 | 只记非显然决策 |
| `handoff.md` | 给下一个会话或客户端的交接卡 | ≤30 行 |
| `evidence/` | 命令输出、测试报告、截图等原件 | 正文只引用路径与关键行 |

字段与模板见 `references/templates.md`。

## 阶段一：收敛立项

1. **判定入口**：只有用户表达「整理成任务 / 确认后执行 / 继续上次」才立项；纯讨论不立项。
2. **自己抽取，不让用户重述**。来源是当前对话、用户给的文件和仓库现状，抽取六类信息：
   - 目标结果：一句话，能判断是否达成。
   - 验收标准：逐条列出，尽量可机器验证。
   - 范围与非目标：尤其写清「不做」。
   - 已决事项与被否决方案及理由。
   - 未决项 → 默认假设：≤3 条，冲突再回报，不要停下来反复问。
   - 授权边界与预算。
3. **验收写不出来时**：把第一轮定为「探索轮」，产出验收候选，不要凭感觉开跑。
4. 写入 `task.md` 与 `state.json`（`status=pending_confirmation`，`round=0`）。
5. 只输出**任务契约卡**（≤40 行，见 `references/templates.md`），结尾写「回复确认开始，或指出要改的条目」。
6. 用户提出修改：更新契约，回到待确认；不要边改边执行。

## 阶段二：确认门

- 明确确认才算：`确认 / 可以 / 按这个来 / 开始执行`。含糊回应（「嗯」「不错」）不算，追问一次。
- 确认后：`status=active`，记录确认时间与授权级别，生成首版 `handoff.md`。
- 默认必须确认；只有「完全可逆 + 仅工作区内 + 影响面小」且用户明示开启自动立项时，才可跳过。

## 阶段三：自主执行（每轮六步）

1. **读**：只读 `state.json` + `task.md` 的验收与已决段 + `progress.md` 末 3 轮。禁止复述全历史。
2. **选**：确定本轮 `next_action`，必须一轮内可完成、有验证方式、前置已满足，并写入 `state.json`。
3. **做**：只做本轮唯一目标；写操作前记录回滚点（有版本控制记提交号，否则记备份路径）；大输出落 `evidence/`。
4. **验**：按验收项类型验证（命令退出码 / 文件断言 / 外部返回 / 人工）。失败时记录命令、关键报错、已试方案，不要原样重试。
5. **记**：更新 `state.json`、追加 `progress.md`、必要时刷新 `handoff.md`。
6. **判**：命中停止规则就停并给停止报告；否则自动度允许时进入下一轮，不允许时输出续跑块。

单轮上限：1 个目标、1 次验证、≤25 次工具调用、单条命令默认超时 5 分钟（更久就转后台或拆轮）。

## 自主度与跨客户端降级

每个任务做一次能力探测，写入 `state.capabilities`，按实际能力选档，不按客户端名字猜：

| 档位 | 判据 | 行为 |
|---|---|---|
| L1 自动续跑 | 客户端有会话级目标、循环或自动继续机制 | 未命中停止规则就自己进入下一轮，只在必须打断时打断 |
| L2 单指令续跑（默认） | 能连续调用工具，但没有自动续跑 | 单次响应内尽量推进，结束时输出续跑块 |
| L3 交接恢复 | 新会话、上下文已压缩或更换客户端 | 读 `handoff.md` 与 `state.json` 恢复，先复述「第 N 轮、下一步 X」再继续 |

**必须诚实说明**：没有自动续跑机制的客户端，跨响应仍需用户一句「继续」。不要在技能里假装能后台常驻。探测项、降级细则与跨平台写法见 `references/clients.md`。

## 停止与阻塞（硬规则）

| 条件 | 处理 |
|---|---|
| 验收全绿，人工项已由用户确认 | `done`，输出交付报告 |
| 连续 2 轮没有新增完成项或证据 | 换一次策略；仍无进展就汇报并停 |
| 同一阻塞连续 3 轮 | `blocked`，列出需要用户提供什么 |
| 轮次、时长或成本预算耗尽 | `stopped`，报告进度与剩余项 |
| 需要超授权、不可逆操作或目标自相矛盾 | 立即暂停并说明 |

任何情况下都不允许无上限自动推进。

## 验证与证据

- 证据类型：命令结果、文件断言、外部返回、人工确认。人工项不得自判完成。
- 每完成一个里程碑，下一轮以评审者身份只读证据复查（不复用实现时的心智），不符就回退。
- 交付报告：验收逐条打勾 + 证据引用 + 变更清单 + 回滚点 + 遗留风险与假设。

## 授权与安全

| 操作 | 默认 |
|---|---|
| 只读分析 | 允许 |
| 工作区内写 | 允许 |
| 工作区外写、删除 | 需确认 |
| 提交、推送、发布、发消息、付费等外发或不可逆操作 | 需确认 |

不读取或传递凭据；写入不越出约定范围；预算与停止条件由用户可改。

## 上下文预算

每轮只加载状态摘要；大输出落盘、正文只留摘要；每 5 轮压缩一次 `progress.md`；不在对话里重述背景，`task.md` 是唯一事实源。

## 汇报与打断

- 正常时按里程碑汇报（验收进度 x/y、本轮证据、下一步），不要每轮长篇。
- 只有四种情况打断用户：需要决策的阻塞、需要超授权、目标有矛盾、不可逆风险。

## 反模式

- 讨论还没收敛就立项开干。
- 没有可验证验收就「自主推进」。
- 一轮做多件事、一轮多次验证。
- 用「我觉得完成了」代替证据。
- 失败后原样重试。
- 无预算、无停止规则地自动推进。
- 把某个客户端的机制写成通用前提。
- 中间产物只留在对话里，不落盘。
